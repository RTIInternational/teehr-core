# Golden metric values

Reference values the engine is tested against from P1 on. Generated by `scripts/fixtures/compute_golden.py`; never edit by hand.

| File | What it holds | How it's computed |
|------|---------------|-------------------|
| `metric_vectors.json` | Small hand-made cases, including edge cases (constant obs/sim, obs summing to zero, a single pair) | Exact arithmetic (`fractions`, 50-digit `decimal`), no NumPy or metric libraries |
| `hydro_metrics.json`, `energy_metrics.json` | Metrics for each fixture, grouped by location × predicted dataset and by location × predicted dataset × 6 h lead-time bin | Pairing and grouping in plain pandas (independent of the engine); every value computed by at least two libraries plus exact arithmetic, which must agree before it's written |

Definitions (also stored in each file): `count`, `mean_error`, `relative_bias`, `rmse`, `nse`, `kge` (2009), `pearson_r`. A value is `null` when it's mathematically undefined, for example NSE when observations are constant. That's the missing-data policy the engine must follow.

Changing a golden value requires a CHANGELOG entry explaining why.
